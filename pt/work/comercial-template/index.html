01Problema

O problema que o projeto enfrenta são propostas feitas em documentos e planilhas: total calculado à mão, nenhum histórico por cliente e um PDF apresentável que precisa ser formatado de novo a cada vez. O projeto testa se esse fluxo (cliente → proposta → itens → total → PDF) cabe numa aplicação pequena, confiável e reaproveitável.

02Contexto

É uma aplicação de demonstração, com interface em português e dados sintéticos. Não está publicada nem tem usuários, e não alega adoção em produção.

03Solução

  • Cadastro e login com e-mail e senha, senha com hash bcrypt e sessão JWT.
  • Painel protegido, com criação, lista e detalhe de clientes e de propostas.
  • Itens com quantidade, preço e total arredondado em centavos.
  • PDF de cada proposta gerado no servidor, que só o dono baixa.

04Arquitetura

Uma única aplicação Next.js (App Router) em TypeScript. As páginas são React Server Components que consultam o banco via Prisma (SQLite); as gravações passam por Server Actions; uma rota gera o PDF com @react-pdf/renderer. Um middleware bloqueia as rotas protegidas sem sessão. Há Dockerfile e build standalone configurados.

05Evidências

  • Passou em 24/24 testes unitários (4 arquivos: dinheiro, server actions, middleware e rota de PDF), com typecheck limpo, na execução feita para este site em 19/10/2026.
  • O CI passou no commit atual. O workflow "Web validation" roda instalação, lint, testes unitários, build de produção, typecheck e um smoke test no navegador contra o build de produção.
  • O isolamento de dados é testado: a rota de PDF responde 401 sem sessão e 404 para propostas de outro usuário, e a criação de proposta recusa cliente de outro usuário.
  • O repositório documenta uma execução no navegador em 07/10/2026 com 13/13 checagens, entre elas um segundo usuário recebendo 404 nos registros do primeiro. Essa execução não foi repetida para este site.

08Limitações

  • Sem demo hospedada nem deploy.
  • Imagem Docker não verificada: o Dockerfile copia uma pasta public/ que não existe.
  • Clientes e propostas não podem ser editados nem apagados, e o status da proposta não muda pela interface.
  • Sem verificação de e-mail, recuperação de senha nem limite de tentativas de login.
  • Valores guardados em ponto flutuante (arredondados por linha), com BRL e pt-BR fixos no código.
  • Esquema aplicado com db push, sem histórico de migrações.
  • Restam 11 alertas de severidade alta em dependências de ferramentas e opcionais (0 críticos), segundo npm audit em 19/10/2026.
  • Sem testes de desempenho, acessibilidade ou segurança.
  • O header vaza horizontalmente abaixo de ~420 px (medido a 360/390 px); o botão 'Ver demo' tem contraste 1.04:1 e o rodapé 3.66:1 (WCAG AA exige 4.5:1).
  • Sem arquivo LICENSE.

09Necessidade comercial
