FLOWDESK · AI Operations Demo

1. Problema

Pedidos chegam por formulários e caixas de entrada. Alguém lê cada um, decide o que é e qual a urgência, escreve uma resposta e acompanha o caso. Quase tudo é rotina, mas a resposta ainda precisa do julgamento de uma pessoa.

2. Contexto

O FLOWDESK é a demonstração da ARBOCK LABS para a S01 · Business Automation & AI. Usa só dados sintéticos.

3. Solução (escopo)

Formulário → Triagem → Sugestão de resposta → Aprovação humana → Registro. 1. Formulário de pedido. 2. Persistência, com lista e detalhe. 3. Categoria e prioridade automáticas. 4. Sugestão de resposta editável. 5. Aprovar ou rejeitar. 6. Histórico de eventos de cada pedido. 7. Painel responsivo. 8. API e webhook. 9. Estados de erro e de lista vazia. 10. Documentação.

Sobre a "IA": nesta demonstração, a sugestão de resposta é gerada por regras e vem rotulada como "Simulação (regras) — não é um modelo de IA" na interface e na API. A camada de sugestão fica atrás de uma interface de provedor, para que um modelo de linguagem real possa ser conectado depois, só com um provedor autorizado. Uma regra fixa nunca é apresentada como modelo.

4. Arquitetura

Front-end estático com API em Cloudflare Workers e banco D1, rodando localmente com Wrangler. A conta Cloudflare para a hospedagem ainda não existe, então nada está publicado.

5. Evidências

  • O código está commitado num repositório local (commit bd8a1c9, 19/10/2026). Segundo a mensagem do commit, ele inclui o esquema D1, a triagem por regras, um provedor de sugestão desacoplado, uma máquina de estados, webhooks assinados, uma API REST e a interface.
  • O rótulo "Simulação (regras) — não é um modelo de IA" está definido no código e aparece na interface.
  • Ainda não verificado pelo QA.

6. Papel humano e ferramentas de IA

A aprovação humana é uma etapa obrigatória dentro do próprio produto: nada conta como "respondido" sem uma pessoa aprovar, e a demonstração não envia e-mail real. O software é feito com desenvolvimento assistido por IA sob direção humana.

7. Testes executados

Nenhum registrado ainda. Testes unitários e de integração em CI são critérios de aceite desta demonstração.

8. Limitações (conhecidas de antemão)

  • A sugestão de resposta é por regras, não por um modelo de linguagem.
  • Só demo local; hospedagem pendente (conta não criada).
  • Depois de hospedado, valem os limites do plano gratuito.

9. Necessidade comercial

Mostra o formato de uma automação em que o software faz a triagem e o rascunho e a pessoa fica com a decisão. É o núcleo da S01.
