01Problema

Pedidos chegam por formulários e caixas de entrada. Alguém lê cada um, decide o que é e qual a urgência, escreve uma resposta e acompanha o caso. Quase tudo é rotina, mas a resposta ainda precisa do julgamento de uma pessoa.

02Contexto

O FLOWDESK é a demonstração da ARBOCK LABS para a S01 · Business Automation & AI (automação de processos de negócio com IA). Usa só dados sintéticos, não envia e-mail e não foi publicado: ainda não existe conta Cloudflare.

03Solução

Formulário → Triagem → Sugestão de resposta → Aprovação humana → Registro. - Formulário de entrada. Envios inválidos são recusados com mensagens por campo. - Triagem por regras, que define categoria e prioridade e registra os motivos. - Sugestão de resposta editável. Vem rotulada como "Simulação (regras) — não é um modelo de IA" na interface e na API, e a API marca o provedor como is_ai_model: false. - Aprovação humana obrigatória. Não dá para aprovar um pedido antes de existir sugestão. Aprovar exige um revisor identificado, rejeitar exige um motivo, e nenhum e-mail é enviado. - Histórico de eventos de cada mudança de estado e de cada edição humana, com o autor. - Webhooks assinados a cada mudança de estado, com assinatura HMAC-SHA256 que o receptor confere. - Estados de erro e de lista vazia na API e na interface.

O arquivo de status do desenvolvedor dá como feitas as 10 funcionalidades exigidas no briefing; o painel responsivo é conferido só por testes automatizados.

04Arquitetura

Um Cloudflare Worker que serve uma interface estática e uma API REST, com banco D1 (SQLite). Localmente, roda com wrangler dev --local (miniflare/workerd). As sugestões vêm de uma interface de provedor substituível. Hoje o único provedor é a simulação por regras, então conectar um modelo real depois significa acrescentar um provedor, o que exige um provedor autorizado.

05Evidências

Os testes abaixo rodaram localmente em 19/10/2026, sobre um código idêntico ao do commit citado: - Testes unitários e de integração: passaram 53 de 53 em 2 arquivos, com typecheck exit 0. - Testes de ponta a ponta no navegador: 22 checagens passaram, 0 falharam. Cobrem: - o rótulo de simulação na interface; - um ataque XSS exibido como texto puro; - triagem → sugestão → edição → aprovação → registro, e rejeição com motivo; - um histórico de 6 eventos; - o estado de lista vazia; - nenhum transbordo horizontal em 360, 768 e 1280 px; - nenhum erro de console. - Demonstração da API com curl. A resposta da sugestão traz o rótulo de simulação e is_ai_model: false. Aprovar um pedido novo é recusado como transição inválida. Entrada inválida responde 400 e um corpo de 100 KB responde 413. Um preflight de outro site responde 403. O limite de envios responde 429. - Webhooks. Um receptor externo conferiu 5 de 5 eventos assinados. Um pedido com assinatura correta respondeu 200; uma assinatura forjada respondeu 401. - Checagens estáticas aprovadas: nenhum ponto de injeção de HTML, valores sempre vinculados nas consultas SQL, nenhum segredo nos arquivos versionados. - gitleaks no histórico completo não encontrou vazamentos. - npm audit encontrou 0 vulnerabilidades.

06Papel humano e ferramentas de IA

08Limitações

  • As sugestões são por regras: uma simulação, não um modelo de IA.
  • Demo local; hospedagem pendente. Não há conta Cloudflare e nada está publicado, então o comportamento em produção não foi observado.
  • O CI nunca rodou. O arquivo de workflow existe, mas o repositório não tem remoto.
  • axe/pa11y e Lighthouse não foram rodados. Acessibilidade e desempenho não foram medidos.
  • As rotas de escrita não têm autenticação: quem acessar o servidor pode aprovar ou rejeitar. Isso só é aceitável com dados sintéticos.
  • Os webhooks são enviados uma vez, com timeout de 5 segundos e sem nova tentativa; as falhas ficam registradas como falha.
  • O limite de envios é uma janela fixa simples, não serve contra abuso.
  • A interface está em inglês, com exceção do rótulo de simulação em português.
  • O trufflehog não foi rodado.

09Necessidade comercial

Mostra o formato de uma automação em que o software faz a triagem e o rascunho, a pessoa fica com a decisão e cada passo deixa registro. É o núcleo da S01.
