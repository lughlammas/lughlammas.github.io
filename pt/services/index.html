Serviços

São três ofertas. Cada uma começa com uma avaliação e termina com algo que você pode rodar, testar e ler. Não prometemos resultado fechado antes de ver o código ou o processo.

S03 · AI Code Rescue & Technical Delivery (oferta prioritária)

Resgate de código feito com IA e entrega técnica.

Para quem

Para quem usou uma ou várias ferramentas de IA para programar e agora tem um código que quase funciona. Ou para quem herdou um código sem a pessoa que o escreveu.

Problemas que resolve

  • O projeto não instala, não compila ou não sobe numa máquina limpa.
  • Faltam testes, ou eles existem e falham, ou passam sem testar nada que importe.
  • O README descreve funcionalidades que o código não tem, ou omite as que ele tem.
  • Há segredos, chaves ou dados pessoais junto do código ou no histórico.
  • Há pastas, cópias e branches duplicados, e ninguém sabe qual é o canônico.
  • Há dependências com alertas de segurança conhecidos.
  • Ninguém sabe dizer o que é seguro publicar.

O que você recebe

  1. Relatório de avaliação: inventário do que existe; o que instala, compila e roda, com os comandos e as saídas exatas; o que o README promete comparado com a realidade; e os riscos, classificados em "seguro mudar", "precisa de revisão" e "precisa da sua aprovação".
  2. Plano de estabilização: lista ordenada de correções, cada uma com seu critério de aceite, que você aprova antes da implementação.
  3. Implementação dos itens aprovados: commits pequenos, num branch separado, sem nunca forçar push no seu branch principal.
  4. Registro de verificação: cada teste, build ou checagem com o comando e a saída. O que não foi rodado aparece como não rodado.
  5. Handoff: README atualizado, limitações conhecidas e o que ficou em aberto.

Como validamos

  • Nada conta como "passou" sem ter sido executado; o comando e a saída vão para o registro.
  • O que o README afirma é conferido contra o código e o build rodando, e não o contrário.
  • Diante de ambiguidade (duas versões candidatas, fonte faltando), o trabalho para naquele item e a dúvida vai para você, sem chute.
  • Ações irreversíveis (apagar branches ou histórico, mudar visibilidade ou licença, mexer em segredos ou em produção) só acontecem com a sua aprovação explícita.

O que NÃO prometemos

  • Que todo projeto tem salvação. Às vezes a avaliação conclui que reescrever sai mais barato, e você fica sabendo disso antes de gastar mais.
  • Segurança. Relatamos os alertas, segredos e riscos que as ferramentas que rodamos encontraram. Isso não é auditoria nem certificação de segurança.
  • Deploy ou disponibilidade antes de avaliar o ambiente de destino.
  • Números de desempenho que não medimos.
  • Reescrever o seu histórico Git ou apagar qualquer coisa sem a sua aprovação por escrito.

Evidência desse jeito de trabalhar

São projetos próprios, não resgates para clientes: - A auditoria e consolidação, por iniciativa própria, de uma conta inteira do GitHub e de um workspace local: inventário, detecção de duplicados, varredura de segredos no histórico de 41 repositórios (0 ocorrências) e parada em cada projeto ambíguo. Não foi trabalho pago para cliente. - No comercial-template, um alerta crítico do framework foi eliminado com a atualização do Next.js (commit 0e9e5db), e os alertas restantes estão documentados, não escondidos.

S02 · Custom Software & MVP Development

Software sob medida e desenvolvimento de MVP.

Para quem

Para quem precisa de uma primeira versão funcional de uma aplicação web, suficiente para mostrar, testar com usuários reais ou servir de base.

O que você recebe

  • Uma primeira versão com escopo definido: o fluxo principal, autenticação quando necessária, persistência e as telas que importam.
  • Testes automatizados para a lógica que carrega risco (dinheiro, permissões, dono dos dados).
  • Um README com instalação, comando para rodar, o que está implementado e as limitações conhecidas.
  • Um repositório versionado com histórico legível.
  • Dados sintéticos para demonstração, nunca os seus dados reais.

Como validamos

  • Os critérios de aceite, do tipo passa/não passa, são combinados antes de começar.
  • Os testes são rodados e a saída fica registrada; o CI é configurado quando o projeto permite.
  • As limitações vão escritas na entrega, em vez de serem descobertas depois.

O que NÃO prometemos

  • Garantias de hospedagem em produção, escala ou segurança, a não ser que tenham escopo e avaliação próprios.
  • Funcionalidades além dos critérios combinados dentro do mesmo escopo.

Projeto de referência

comercial-template: autenticação, dados isolados por usuário, fluxos de clientes e propostas e PDF no servidor. Passou em 24/24 testes unitários e o CI passou no commit atual. Entre as limitações documentadas estão a falta de deploy hospedado e a imagem Docker não verificada.

S01 · Business Automation & AI

Automação de processos de negócio com IA.

Para quem

Para quem faz todo dia a mesma recepção, triagem e resposta de pedidos.

O que você recebe

  • O processo mapeado: por onde os pedidos chegam, como são classificados, quem decide.
  • Um fluxo funcionando: entrada → triagem automática → resposta sugerida → aprovação humana → registro.
  • Cada passo automatizado traz um rótulo que diz se é regra ou modelo de linguagem. Regra fixa nunca é apresentada como IA.
  • Provedores de IA conectados só com a sua autorização e na sua conta, atrás de uma interface que pode ser trocada.
  • Logs e histórico de eventos, para você ver o que aconteceu e por quê.

Como validamos

  • Cada etapa do fluxo é testada com dados sintéticos.
  • Nada é enviado aos seus clientes sem uma pessoa aprovar.

O que NÃO prometemos

  • Economia garantida de tempo ou de custo. Ainda não medimos nenhuma, então não citamos nenhuma.
  • Respostas totalmente automáticas aos seus clientes.
  • Custo de provedor de IA escondido no preço: se for preciso um modelo pago, a decisão e a conta são suas.

Projeto de referência

FLOWDESK é a demonstração desta oferta. É uma demo local, com hospedagem pendente.
