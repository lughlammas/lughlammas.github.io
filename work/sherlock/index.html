SHERLOCK

A visual chess investigation and analysis environment. Repository: https://github.com/lughlammas/sherlock · commit e632035 · Android release v0.1.3

1. Problem

A chess engine is a command-line program that speaks a text protocol (UCI). Putting it behind a visual interface raises integration problems: starting and stopping the process, parsing its output, cancelling a search, and making sure that a late answer from an old search never overwrites the current position.

2. Context

Its own project, also used as an engineering showcase. It integrates the engine Lughnasadh, version 0.2. A newer engine version (0.4.0) is maintained separately and has not been integrated or validated in SHERLOCK.

3. Solution

  • Responsive board; load, copy and reset positions (FEN).
  • Analysis by depth or by time, with live depth, nodes, speed, evaluation and principal line, and a stop button.
  • Clear states: ready, investigating, best move, engine error (with retry and restart).
  • A mode in which two engine processes play each other.
  • An Android version.

4. Architecture

Browser (React) → WebSocket → SHERLOCK controller → Lughnasadh adapter → engine as a child process. The interface never speaks raw UCI; the adapter owns the protocol, timeouts and session tokens, so stale replies are discarded, and the board position survives an engine timeout, crash or restart. On Android, the same interface runs in a WebView and reaches the native engine through a JavaScript bridge and ProcessBuilder, with no Node or WebSocket dependency in the APK.

5. Evidence

  • 8/8 tests passed in the run for this site on 2026-10-19: 6 UCI-parser tests and 2 session tests, including "drops stale info when session rotates". Typecheck clean.
  • Release v0.1.3 with its APK is public on GitHub, and the repository publishes the APK's SHA-256.

6. Human role and AI tools

Built through human-directed AI-assisted development.

8. Limitations

  • No continuous integration.
  • Tests use mocked engine lines; real-engine behaviour is covered only by smoke scripts that were not run here.
  • Integrated engine is version 0.2; 0.4.0 not integrated.
  • No playing-strength or performance benchmark.
  • Engine-versus-engine mode runs two processes and uses substantial battery and memory.

9. Commercial relevance

SHERLOCK shows integration work: a native process, a text protocol, a real-time interface and mobile packaging, with the failure cases (timeouts, crashes, late replies) handled explicitly. That is the kind of plumbing behind S02 · Custom Software and the diagnosis in S03 · AI Code Rescue.
