01Problem

Requests arrive through forms and inboxes. Someone reads each one, decides what it is and how urgent it is, writes a reply and keeps track of it. Most of that is routine, but the reply still needs a person's judgement.

02Context

FLOWDESK is ARBOCK LABS' demonstration for S01 · Business Automation & AI. It uses synthetic data only, sends no email, and has not been deployed: there is no Cloudflare account yet.

03Solution

Form → Triage → Reply suggestion → Human approval → Record. - Intake form. Invalid submissions are refused with per-field messages. - Rule-based triage sets a category and a priority, and records the reasons. - Editable reply suggestion. It is labelled "Simulação (regras) — não é um modelo de IA" in the interface and in the API, and the API marks the provider as is_ai_model: false. - Human approval is mandatory. A ticket cannot be approved before a suggestion exists. Approving needs a named reviewer, rejecting needs a reason, and no email is ever sent. - Event history for every state change and every human edit, with who made it. - Signed webhooks on every state change, with an HMAC-SHA256 signature that the receiver checks. - Error and empty states in the API and in the interface.

The developer's status file lists all 10 features required by the brief as done; the responsive panel is checked by automated tests only.

04Architecture

A Cloudflare Worker serving a static interface and a REST API, with a D1 (SQLite) database. Locally it runs on wrangler dev --local (miniflare/workerd). Suggestions come from a pluggable provider interface. The only provider today is the rules simulation, so connecting a real model later would mean adding a provider, which needs an authorised provider.

05Evidence

The tests below ran locally on 2026-10-19, against code identical to the cited commit: - Unit and integration tests: 53 of 53 passed in 2 test files, with typecheck exit 0. - Browser end-to-end: 22 checks passed, 0 failed. They cover: - the simulation label in the interface; - an XSS payload rendered as plain text; - triage → suggestion → edit → approve → register, and reject with a reason; - a 6-entry event history; - the empty state; - no horizontal overflow at 360, 768 and 1280 px; - no console errors. - API demo with curl. The suggestion response carries the simulation label and is_ai_model: false. Approving a fresh ticket is refused as an invalid transition. Invalid input returns 400 and a 100 KB body returns 413. A cross-site preflight returns 403. The intake rate limit returns 429. - Webhooks. An external receiver verified 5 of 5 signed events. A correctly signed request returned 200; a forged signature returned 401. - Static checks passed: no HTML-injection sinks, values bound in every SQL query, no secrets in tracked files. - gitleaks over the full history found no leaks. - npm audit found 0 vulnerabilities.

06Human role and AI tools

Human approval is a step inside the product: nothing is approved or registered without a person acting, and every action is logged with its author. The software was built through human-directed AI-assisted development.

08Limitations

  • Suggestions are rule-based: a simulation, not an AI model.
  • Local demo; hosting pending. There is no Cloudflare account and nothing is deployed, so production behaviour has not been observed.
  • CI has never run. A workflow file exists, but the repository has no remote.
  • axe/pa11y and Lighthouse were not run. Accessibility and performance have not been measured.
  • No authentication on write routes: anyone who reaches the server can approve or reject. That is acceptable only with synthetic data.
  • Webhooks are sent once, with a 5-second timeout and no retry; failures are recorded as failed.
  • The rate limit is a simple fixed window, not abuse-grade.
  • The interface is in English, apart from the Portuguese simulation label.
  • trufflehog was not run.

09Commercial relevance

It shows the shape of an automation in which software does the sorting and drafting, a person keeps the decision, and every step leaves a record. That is the core of S01.
