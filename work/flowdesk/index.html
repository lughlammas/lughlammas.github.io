FLOWDESK · rules-based operations demo

This rebuilt MVP shows a synthetic request moving through triage, an editable suggestion, human approval and a log. Rules-based simulation — no AI model is used. The original Sprint 001 source was not recovered; its test counts do not describe this MVP.

01Problem

Incoming requests need classification, a response and a record. This example shows where rules can help and where a person makes the decision.

02Demo

A visitor creates a synthetic request. Rules assign a category and priority and suggest a response. A person can edit and approve or reject it. The outcome stays in that session’s history. D1 stores separate sessions; the cookie is HttpOnly, Secure and SameSite=Lax.

A token-protected admin route exists but remains disabled until a secret is configured. An optional signed webhook is not connected in this demo.

03Verification

All 6 local tests for the rebuilt MVP passed, covering the HTTP flow, state transitions, isolation, admin authorization, rate limits, cleanup and HMAC signatures. CI passed on the private repository commit used for deployment. At the public URL, creation, triage, suggestion, editing, approval and logging were verified with a synthetic request. The admin route returned “Admin unavailable” without a token.

The older portfolio screenshots and 94/94 and 64/64 counts belong to the unavailable local project; they do not document this rebuilt MVP.

04Limitations

  • Suggestions come from rules, with no AI model.
  • The interface is in Portuguese and accepts synthetic data only.
  • No real delivery or CRM integration is connected.
  • Manual screen reader testing and independent cross-browser isolation checks on the hosted version are still pending.
  • The simple rate limit does not replace large-scale abuse protection.

05Commercial relevance

The flow illustrates triage and drafting with mandatory human approval, related to service S01.
