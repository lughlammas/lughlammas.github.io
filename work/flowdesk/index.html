FLOWDESK · AI Operations Demo

1. Problem

Requests arrive through forms and inboxes. Someone reads each one, decides what it is and how urgent it is, writes a reply and keeps track of it. Most of that is routine, but the reply still needs a person's judgement.

2. Context

FLOWDESK is ARBOCK LABS' demonstration for S01 · Business Automation & AI. It uses synthetic data only.

3. Solution (planned)

Form → Triage → Reply suggestion → Human approval → Record. 1. A request form. 2. Persistence and a list and detail view. 3. Automatic category and priority. 4. An editable reply suggestion. 5. Approve or reject. 6. An event history for each request. 7. A responsive panel. 8. An API and webhook. 9. Error and empty states. 10. Documentation.

About the "AI": in this demo, the reply suggestion is generated by rules and labelled "Simulation (rules) — not an AI model" in the interface and in the API. The suggestion layer sits behind a provider interface, so a real language model can be connected later, only with an authorised provider. A fixed rule is never presented as a model.

4. Architecture (planned)

A static front end on the site, with an API on Cloudflare Workers and a D1 database (free tier), developed and tested locally first. The Cloudflare account does not exist yet.

5. Evidence

Pending. No code has been committed yet.

6. Human role and AI tools

Human approval is a required step in the product itself: nothing counts as "replied" without a person approving it, and the demo sends no real email. The software is built through human-directed AI-assisted development.

7. Tests executed

Pending. Unit and integration tests in CI are acceptance criteria for this demo.

8. Limitations (known in advance)

  • The reply suggestion is rule-based, not a language model.
  • Not hosted yet (account pending).
  • Free-tier limits apply once hosted.

9. Commercial relevance

It shows the shape of an automation in which software does the sorting and drafting and a person keeps the decision. That is the core of S01.
